* package-retry.el

Add retry functionality to Emacs package.el download operations.

** What It Does

Package downloads sometimes fail due to network issues or server problems. This package automatically retries failed synchronous downloads with configurable settings. Package unpacking, build, and compilation errors are not retried.

** Usage

#+BEGIN_SRC elisp
  (use-package package-retry
    :vc ( :url "https://github.com/kn66/package-retry.el.git")
    :config
    (package-retry-mode +1))
#+END_SRC

** Configuration

*** Customizable Variables

| Variable                         | Description                            | Default |
|----------------------------------+----------------------------------------+---------|
| =package-retry-max-attempts=     | Maximum total attempts                 |       5 |
| =package-retry-delay=            | Initial retry delay in seconds         |       3 |
| =package-retry-backoff-factor=   | Delay multiplier after each failure    |       2 |
| =package-retry-max-delay=        | Maximum retry delay in seconds         |      30 |
| =package-retry-jitter=           | Random delay variation                 |     0.1 |
| =package-retry-predicate=        | Function deciding whether to retry     | default |
| =package-retry-enable-message=   | Show retry messages                    |       t |

*** Customize Group

=M-x customize-group RET package-retry RET=

** How It Works

On Emacs 25.1 or later, the package adds advice to package.el's internal response retrieval function so only retrieval errors are retried. On older Emacs versions, it falls back to retrying =url-insert-file-contents= while =package-install-from-archive= is running.

1. A retryable download fails → wait using exponential backoff and retry
2. Package unpack/build fails → show the original error without retrying
3. Known permanent failures, such as HTTP 404, are returned immediately
4. Max attempts reached → show the original download error
5. Success → continue normally

The default predicate avoids retrying known programming errors, permanent
HTTP failures, and invalid certificates. Unknown retrieval errors remain
retryable for compatibility. Set =package-retry-predicate= to a custom
function when an archive needs a different policy.
